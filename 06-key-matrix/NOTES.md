# 06 矩阵按键 · 阅读与调试笔记

芯片 AT89C51 / 11.0592 MHz，Keil C51，板载 4×4 矩阵键盘接 P1，数码管段选接 P0。

## 一、两种扫描方式，本质是同一件事的两种问法

代码里有两个函数，结果一样，成本不一样。

**行列扫描（`key_matrix_ranks_scan`）**：把某一列拉低、其余拉高，然后整字节读回 P1。
行线被按下时会被拉低，于是读回值里出现一个 0 位，位置就对应某一行。
四列依次扫一遍，最多写 4 次端口、读 4 次，代码 100 行里有 60 行是 `switch`。

**线翻转（`key_matrix_flip_scan`）**：先给全部行 0、列 1（`0x0f`）判断"有没有键按下"，
再用 `0x0f` 读出列号，用 `0xf0` 读出，配合 `+4 / +8 / +12` 换算出行号。
写 3 次端口就够，代码短一半。

差异的关键不在长度，在**可读性**：行列扫描把 16 个键值硬编码成 16 个 case，
线翻转用 `行偏移 + 列号` 算出来。板子换一种接法时，前者要重排 16 个常数，后者只改那张 4 项的小表。

## 二、消抖那 10 ms 是在干什么

```c
if (KEY_MATRIX_PORT != 0xf7)   // 检测到可能按下
{
    delay_10us(1000);          // 约 10 ms
    switch (KEY_MATRIX_PORT)   // 再读一次，这次的值才算数
    ...
}
```

机械触点在闭合瞬间会弹跳 5–20 ms，端口上能看到一串 0/1 抖动。
直接读第一下，一次按键可能被当成按了三四次。

这里的写法值得注意：**消抖之后没有再写一句 `if`，而是直接 `switch`**。
因为如果抖动过后键其实已经松开，读回值就是 `0xf7`，16 个 case 一个都命中不了，
`key_value` 保持 0 —— 判定自动失败。等于用查表顺手做了第二次确认，省掉一层嵌套。

代价是：`delay_10us(1000)` 是死等，这 10 ms 里 CPU 什么也做不了。

## 三、这套课程代码的工程缺陷（能跑，但别照抄进项目）

1. **`while (KEY_MATRIX_PORT != 0xf7);` 是阻塞等待松手**。
   按住不放，主循环就卡死在这里，别的任务全停。实际项目要改成「记录上次电平 + 状态机」，
   由定时器每 10 ms 采一次，主循环永不阻塞。
2. **整字节赋值 `P1 = 0xf7` 会覆盖 P1 的其它位**。
   这块板的 P1 全给了键盘，所以没事；换成 P1 上还挂着别的外设的板子，就会误改别人的电平。
   规矩做法是 `P1 = (P1 & 0xf0) | 0x07`，只动低 4 位。
3. **`u8 gsmg_code[17]` 初始化了 16 个值**，数组实际长度 17，末尾那个恒为 0。
   不影响运行，但说明是从别的实验复制过来的，长度该跟着改。

## 四、上板可以自己验证的两件事

- 把 `delay_10us(1000)` 改成 `delay_10us(50)`（约 0.5 ms）：按下时会不会出现重复键值？这就是消抖失效的样子
- 把 `delay_10us(1000)` 改成 `delay_10us(5000)`（约 50 ms）：按键会不会"发粘"、快按没反应？

这两个方向都能把「消抖时间不是越小越好，也不是越大越好」变成能看见的现象，而不是背下来的结论。
